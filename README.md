# 互文 · 游戏文学考据

一个纯静态的考据档案站。没有数据库，没有后端，没有构建步骤——双击 `index.html` 就能看，改一个文本文件就能加一条。

```
game-lit-codex/
├─ index.html            站点外壳（一般不用动）
├─ assets/
│  ├─ style.css          样式（改颜色、字号在这里）
│  └─ app.js             渲染逻辑（一般不用动）
├─ data/
│  ├─ entries.js         ← 条目库，日常加内容主要改这里
│  ├─ topics.js          ← 待考议题，加这里
│  └─ series.js          ← 专题（把若干条目聚成一组，可带原典对照表）
├─ tools/
│  ├─ check.js           内容体检：查重复 id、坏引用、缺字段
│  └─ render-test.js     渲染自检：逐条路由跑一遍，查报错
└─ README.md
```

---

## 一、怎么打开

双击 `index.html`。就这样。

推荐用 Edge / Chrome。手机上看也行（侧边栏会收成左上角的 ☰）。

如果浏览器顶部出现「已阻止某些内容」之类的提示，不用管——这个站没有任何外部请求，也没有追踪脚本。

## 二、怎么加一条考据

1. 用文本编辑器打开 `data/entries.js`（记事本、VS Code、Sublime 都行）。
2. 找到文件末尾的 `];`，在它**前面**插入一个新块。
3. 复制一条现成的，照下面这个模板改：

```js
{
  id: "short-slug",                    // 唯一，英文小写+连字符，会进网址
  title: "《游戏》与《著作》：副标题",
  category: "quote",                   // quote | motif | reading | edition | mechanic | adapt
  origin: "human",                     // human 成员撰写（**）| ai 示例（*）
  series: "limbus",                    // 可选：专题 id，见 data/series.js
  game: { title: "游戏名", year: "2020", studio: "工作室" },
  work: { title: "著作名", author: "作者", year: "1854", medium: "book" },
  tags: ["关键词", "关键词"],
  updated: "2026-11-03",
  quote: {
    text: "引文",
    lang: "英",                        // 原文语种
    source: "出处：卷 / 章 / 节",       // 精确到章节
    note: "译文说明，或所据译本"         // 缺这句会被体检脚本提醒
  },
  summary: "一句话概述，显示在卡片上。",
  body: ["第一段", "第二段"],
  notes: [{ label: "版本", text: "……" }],
  related: ["另一条的id"]
}
```

4. 保存，刷新浏览器。左侧导航、首页统计会自动更新。

**两个容易踩的坑：**

- 块与块之间要有**英文逗号**，最后一块后面**不要**逗号。
- 中文字符串里不要用英文双引号 `"`，要用「」或『』，否则会提前结束字符串。

### 星号：这条是谁写的

标题右上角有一个标记：

| 标记 | 含义 | `origin` 值 |
|---|---|---|
| `*` | AI 起草的示例，用来占位、搭骨架，还没人核实 | `"ai"` |
| `**` | 社团成员撰写，内容由他负责 | `"human"` |

**自己写的一律填 `human`**，忘了填会被当成 `*`（宁可标低，也不要冒认）。现在站里 14 条全是 `*`——它们是骨架，等着被一条条改成 `**`。

这不是免责声明，是进度表：每一条从 `*` 变成 `**`，才算真正完成。

### 类别只能填这七个

| id | 名称 | 放什么 |
|---|---|---|
| `quote` | 引文与出处 | 游戏直接引用的文本，以及它出自哪一版 |
| `motif` | 母题与原型 | 神话、传说、文学母题如何被重新组装 |
| `reading` | 文本细读 | 不给「出处」，只谈游戏文本自身的文学性 |
| `edition` | 译本与版本 | 同一句引文的译本差异、版本问题 |
| `mechanic` | 机制与叙事 | 玩法本身如何承担叙事与文学表达 |
| `adapt` | 跨媒介改编 | 小说、电影、游戏之间的转写：什么被保留，什么必然丢失 |
| `image` | 图像与视觉 | 版画、插图、绘画与游戏画面之间的互文：构图、光、比例 |

### 媒介：书、电影、戏剧、诗、神话

`work` 这一侧不限于书。加一个 `medium` 字段就行：

| medium | 显示为 | 门类 / 编号 | 用在哪 |
|---|---|---|---|
| `book` | 书（默认，可省略） | 文学 · 第五艺术 | 小说、论著、史书 |
| `film` | 电影 | 电影 · 第七艺术 | 电影改编、影史对照 |
| `painting` | 绘画 | 绘画 · 第三艺术 | 版画、插图、油画（如多雷的《圣经》木刻） |
| `play` | 戏剧 | 戏剧 | 话剧、诗剧 |
| `poem` | 诗 | 文学 · 第五艺术 | 史诗、诗集、俳句 |
| `myth` | 神话 | 口头传统 | 神话材料、传说集 |
| `manga` / `tv` | 漫画 / 剧集 | 漫画 · 第九艺术（欧陆） / 电视 · 第八（一说） | 备用 |

> 「第几艺术」这套编号本身是有分歧的：七艺到电影为止，之后摄影、电视、漫画、游戏陆续被排进第八、第九、第十；欧陆传统里第九艺术指漫画，中文语境里普遍指电子游戏。站内标注只是便于对话的坐标，不是定论——真要考据，该追问是谁、在什么时候、为了什么这么叫。

整条以电影为主（没有游戏）时，把 `game` 也标成电影：

```js
game: { title: "局外人", medium: "film", year: "1967", studio: "卢基诺·维斯康蒂" },
work: { title: "局外人", author: "阿尔贝·加缪", year: "1942" }
```

页面上方的字段标签会自动从「游戏 / 制作」变成「影片 / 导演」，卡片上也会多一个「电影」标记。例子见 `data/entries.js` 里的 `letranger-film`。

条目库页面有两行筛选：第一行按**类别**，第二行按**门类**（只列出数据里真正用到的媒介）。地址形如 `#/entries?cat=image&m=painting`。

要加第七个类别：改 `data/entries.js` 顶部的 `CODEX_CATEGORIES`，加一项 `{ id, name, desc }` 即可，导航和筛选会自动出现。

## 三、怎么加一个议题

打开 `data/topics.js`，同样在末尾 `];` 前加一块：

```js
{
  id: "topic-slug",
  question: "一句话把问题问清楚？",
  status: "征集",                    // 征集 | 整理中 | 已完成
  tags: ["关键词"],
  updated: "2026-11-03",
  entries: ["相关条目的id"],          // 没有就写 []
  body: ["背景说明第一段", "第二段"],
  leads: ["可以从这个方向入手", "还有这个"]
}
```

议题是「还没查清的问题」，讨论在群里发生，结论回填成 `entries.js` 里的新条目。这样讨论不会散掉。

## 四、怎么加一个专题

专题是「把若干条目聚成一组」的东西，比如《边狱巴士》的十二个罪人。定义在 `data/series.js`：

```js
{
  id: "limbus",                       // 条目里写 series: "limbus" 就会归到这里
  name: "边狱巴士 · 十二罪人原典考",
  short: "边狱巴士",                   // 侧边栏用的短名
  eyebrow: "专题",
  desc: "一段整体说明，会显示在专题页顶部和卡片上。",
  roster: [                           // 可选：一张对照表
    { name: "默尔索", work: "局外人", author: "加缪", medium: "book", note: "在母亲葬礼上没哭的人。" }
  ],
  foot: "表格下面的小注，可省略。"
}
```

加完之后：侧边栏「专题」下多一项，首页多一张专题卡，条目里写 `series: "limbus"` 就自动归进去，条目页顶部也会出现「专题 · 边狱巴士」的标记。

`roster` 表适合放「人物 ↔ 原典」这类一一对应的清单，写题纲时先把表填满，再一条条展开成条目。

## 五、改站名、改颜色

- 站名、副标题、首页导语：`data/entries.js` 最上面的 `CODEX_META`。
- 主色（现在是朱砂红 `#a63d2f`）：`assets/style.css` 顶部的 `--accent`。
- 纸底色：同处的 `--paper`。深色模式在 `html[data-theme="dark"]` 那一块。

## 六、改完跑一下检查

装了 Node.js 的话，在项目根目录执行：

```bash
node tools/check.js        # 内容体检
node tools/render-test.js  # 渲染自检
```

`check.js` 会抓出：重复的 id、`related` 指向不存在的条目、缺字段、类别写错、日期格式不对。
`render-test.js` 会遍历每一条路由，报告哪一页报错或渲染出 `undefined`。

没装 Node 也不要紧，浏览器里点一遍就行——但条目多了以后，这两个脚本能省很多时间。

## 七、怎么发布到网上

详细的点击步骤（含 GitHub 网页上传，全程不需要 Git）见 **[DEPLOY.md](DEPLOY.md)**。下面是要点：

三种，从简到繁：

**1. Netlify Drop（最快，五分钟）**
打开 <https://app.netlify.com/drop>，把整个 `game-lit-codex` 文件夹拖进去，得到一个网址。
以后要更新，再拖一次，或在后台连接 Git 仓库。

**2. GitHub Pages（免费，适合长期）**
建一个仓库，把文件夹里的内容推上去，仓库 Settings → Pages → Source 选 `main` / `root`。
网址形如 `https://用户名.github.io/仓库名/`。国内访问可能偏慢。

**3. Cloudflare Pages / Vercel**
同样免费，国内速度通常比 GitHub Pages 好一些。构建命令留空，输出目录填 `/`。

> 如果要绑自己的域名并且服务器在中国大陆，需要备案；用上面这些海外托管则不需要，但速度会受影响。
> 学校社团的话，也可以先只在校内网或群里发压缩包，双击就能看，完全不需要服务器。

## 八、备份

内容只有 `data/` 两个文件。定期把它们复制一份（或者用 Git）即可。
换电脑、换平台、以后想迁到真正的论坛，内容都能原样带走——这是刻意这么设计的。

## 九、关于引文的一条规矩

见站内「关于与凡例」。简述：

1. 引文必须给出处，精确到卷章节；确实取自某译本的要注明译者。
2. 区分**引用**（字句出现）、**化用**（结构意象借用）、**同源**（共享更早的母题）——三者证据强度完全不同。
3. 不确定就标「待补」，放进议题板。空着的条目比编出来的条目有用。
